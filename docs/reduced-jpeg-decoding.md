# Reduced-resolution JPEG decoding

```csharp
using EasyImageSharp.Formats.Jpeg;
using EasyImageSharp.PixelFormats;

using var preview = new JpegDecoder().DecodeReduced<Rgb24>(jpegBytes, scaleDenominator: 4);
```

Denominators 1, 2, 4, and 8 are supported. Output dimensions round upward. A denominator of 1 preserves the normal decoder's output. Source dimension, encoded-byte, and execution limits still apply; choosing a small output does not bypass limits on hostile source headers.

The decoder reconstructs reduced inverse-DCT blocks directly and allocates smaller component sample planes. This avoids a full decoded image followed by resizing. Subsampled chroma may use larger blocks to retain detail at the requested scale. Baseline, extended sequential, progressive, restart markers, grayscale, RGB/YCbCr, and Adobe CMYK/YCCK use the same supported parser as normal JPEG decoding. Unsupported arithmetic/lossless/12-bit JPEG remains unsupported.

Progressive JPEG still retains its full quantized coefficient grid until the scans finish. Entropy parsing still reads the source scans. Reduced decoding therefore saves sample-plane and output storage, but does not promise memory proportional only to the reduced output or a proportional latency improvement. Metadata is retained, including source-coordinate metadata such as EXIF dimensions; callers that save a resized derivative should update metadata as appropriate.

The mathematical reduced transform averages original inverse-DCT sample positions before rounding and clipping; it is not equivalent to resizing the already clipped full-resolution image. Forty-two checked-in independent references generated by Pillow 11.3.0/libjpeg-turbo 3.1.1 cover scales, sampling layouts, progressive/baseline, odd sizes, restart markers, and CMYK/YCCK. Tests require PSNR ≥40 dB and maximum channel error ≤8 relative to these references. See `tests/EasyImageSharp.Tests/Fixtures/generate_jpeg_reduced.py` and its generated provenance JSON for reproducibility. These bounded differences permit decoder rounding differences rather than claiming byte identity with libjpeg.

Use `tools/CoreThroughput` for warmed concurrency, allocation, and process memory measurements on your own JPEG inputs.

The fixture generator is integrated into the complete corpus regeneration check. On 2026-10-14, Python 3.11.9, Pillow 11.3.0 and NumPy 2.4.6 reproduced all 1,298 fixtures with zero differences; [the report](../benchmarks/fixture-determinism-2026-10-14.json) includes the comparison counts. Provenance hashes are verified against each tree's encoded files, while images are compared by decoded pixels so PNG compression differences cannot hide changed content or cause false failures. Three checker regression tests cover compression-only differences, stale hashes and changed pixels.
