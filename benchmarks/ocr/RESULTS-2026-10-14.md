# OCR integration results ? 2026-10-14

Both OCR engines retained exact baseline prediction text and line counts on all 40 crops when replacing released EasyImageSharp 1.1.0 with the current 1.2.0 source build. All six configurations completed: 240 observations, zero processing exceptions. This establishes parity for these inputs, not universal correctness or accuracy.

## Held-out character error rate

Lower CER is better. These character-weighted scores use 20 held-out observations: 10 clean crops and their 10 synthetic controlled counterparts. The paired views are dependent. Source/released baseline scores are identical.

| Configuration | Clean CER | Controlled CER | Combined CER |
|---|---:|---:|---:|
| Paddle baseline | 39.73% | 62.35% | 51.04% |
| EasyOCR baseline | 15.35% | 55.00% | 35.17% |
| Paddle ScannedDocument | 41.94% | 41.45% | 41.70% |
| Paddle PhoneDocument | 49.84% | 44.54% | 47.19% |

ScannedDocument reduced combined Paddle CER by 9.34 percentage points, but worsened clean CER by 2.21 points. PhoneDocument reduced combined CER by 3.85 points while worsening clean CER by 10.11 points. Neither profile is a universal improvement. No default behavior or thresholds were changed in response to these results. Controlled images contain fixed skew, illumination gradient and blur; they are not real photographs.

## Reproducibility and limits

- [Quality summary](results/mdp-block-quality-summary.json) retains all 240 per-observation metrics, tuning/held-out groups, assembly fingerprints, manifest hash and memory measurements.
- [Paddle parity](results/mdp-block-paddleocr-parity.json): 40/40 successful texts identical; zero changed line-count/failure rows; 42 common cached model assets with matching SHA256.
- [EasyOCR parity](results/mdp-block-easyocr-parity.json): 40/40 successful texts identical; zero changed line-count/failure rows; 26 common cached model assets with matching SHA256. Cache fingerprints include unused assets and do not establish which model ran on each image.
- [Corpus provenance](results/mdp-block-corpus-provenance.json) records selection, polygon geometry, label/image hashes and excluded photograph variants. See [methods and reproduction](README.md).
- Raw text exports are local ignored artifacts under [artifacts/ocr-evaluation](../../artifacts/ocr-evaluation). Compact report references resolve relative to their JSON location and include raw-file SHA256. Raw artifacts are regenerated by the documented matrix, not shipped in source control.
- Peak sampled resident memory across runs was 3834.8 MiB, below the 4096 MiB sampled guard; this is not a hard memory bound or a throughput comparison. All five language batches per run were measured.
- This task is text-block recognition with OCR detection, using the largest eligible annotation-selected block per source page. It does not measure full-page reading order, small-text coverage or real-photo OCR. Original full-page output is retained only as a diagnostic because labels omit page elements; original photo polygons are not registered to the photo geometry.
- Only 20 source-page families exist in the entire subset. Shared book/source provenance and model-training overlap are unknown; same-page variant leakage is prevented, but statistical independence is not established. Annotation errors and clipped characters can remain. CER uses Unicode scalar values, case-sensitive trim-only text; whitespace WER is not comparable across all scripts.
