# APNG fixtures

Generated by `gen_apng.py`. Every `<name>.rgba` holds the fully composited canvas for each
animation frame, concatenated in display order, `width * height * 4` bytes of RGBA per frame,
row-major from the top-left. The values come from a NumPy compositor written from the APNG
specification (`_composite`), not from this library and not from Pillow: Pillow 11.3 blends
`APNG_BLEND_OP_OVER` as a straight lerp that also lerps alpha, so it is wrong wherever a source
pixel is partly transparent. Pillow is used as a *cross-check* on the fixtures where that bug
cannot bite, and the `pillow_verified` column records which those are; on those files the
generator asserts Pillow's decode matches the compositor exactly.

Fixture bytes come from two independent writers: `hand-assembled` files are built chunk by chunk
in `gen_apng.py`, which is the only way to control every fcTL field and sequence number, and
`pillow` files are written by Pillow/libpng.

The only decodable fixture(s) carrying a `tolerance` are `over_alpha_general` (1). Every other one is asserted to composite no channel within 0.01 of a half-integer, and the generator additionally re-runs each animation in `float32` - the width C# computes in - and requires the result to be byte-identical, so the comparison really is exact.

Regenerate with `python generate.py` (or `python gen_apng.py`). Cross-check the library's own
encoder output against Pillow with `python gen_apng.py --verify <test output>/apng-roundtrip`.

## Files that must fail

Each is the same well-formed three-frame animation with exactly one thing wrong.
`pillow` records whether Pillow refuses the file too, so "malformed" is corroborated by a
second implementation rather than being this library's private opinion.

| fixture | expected exception | pillow rejects | notes |
| --- | --- | --- | --- |
| `bad_seq_gap` | `InvalidImageContentException` | yes | frame 2's fcTL carries sequence number 7 where 3 was due: the series must have no gaps |
| `bad_seq_reordered` | `InvalidImageContentException` | yes | frame 2's fcTL and fdAT sequence numbers are swapped, so the series runs 0,1,2,4,3 |
| `bad_seq_duplicate` | `InvalidImageContentException` | yes | frame 2's fcTL repeats sequence number 2, which frame 1's fdAT already used |
| `bad_fctl_after_last` | `InvalidImageContentException` | no | acTL declares 2 frames but a third fcTL follows the second frame's data; Pillow accepts it: Pillow stops after acTL's num_frames frames and never looks at the chunks that follow, so a surplus fcTL is simply never read |
| `bad_frame_exceeds_canvas` | `InvalidImageContentException` | yes | frame 2's rectangle starts at x=12 and is 6 wide, so it runs 2 pixels past the 16-pixel canvas |
| `bad_frame_zero_size` | `InvalidImageContentException` | yes | frame 2's fcTL declares a 0x0 rectangle; the specification requires both to be > 0 |
| `bad_fdat_without_fctl` | `InvalidImageContentException` | no | the third frame's data arrives as an fdAT with no fcTL introducing it; Pillow accepts it: acTL declares 2 frames, so Pillow reads 2 and never reaches the third frame's unintroduced fdAT |
| `bad_fdat_orphan_after_frame` | `InvalidImageContentException` | no | a stray fdAT with the next sequence number follows the final frame, which is already complete; Pillow accepts it: Pillow reads the 3 declared frames and stops, never reaching the stray trailing fdAT |
| `bad_first_fctl_offset` | `InvalidImageContentException` | yes | the fcTL that precedes IDAT describes a 14x11 rectangle at (2,1); the fcTL for the default image must be the whole canvas at the origin |
| `bad_num_frames_mismatch` | `InvalidImageContentException` | yes | acTL declares 5 frames but the file only holds 3 |
| `bad_dispose_op` | `InvalidImageContentException` | no | frame 1's dispose_op is 9; only 0, 1 and 2 are defined; Pillow accepts it: Pillow keeps dispose_op verbatim and only compares it against its own three constants, so an out-of-range value silently behaves like APNG_DISPOSE_OP_NONE |
| `bad_blend_op` | `InvalidImageContentException` | no | frame 1's blend_op is 7; only 0 and 1 are defined; Pillow accepts it: Pillow tests `blend_op == OP_SOURCE` and treats every other value as OP_OVER, so an out-of-range value is silently accepted |
| `bad_actl_after_idat` | `InvalidImageContentException` | no | acTL follows IDAT, so the fcTL before IDAT arrives while the file is not yet declared animated; acTL must precede the first IDAT; Pillow accepts it: Pillow only honours an acTL seen before IDAT; a later one is ignored and the file decodes as a still PNG with n_frames 1 instead of raising |
| `bad_two_actl` | `InvalidImageContentException` | no | two acTL chunks; the specification allows exactly one; Pillow accepts it: Pillow warns 'Invalid APNG, will use default PNG image if possible' and falls back to the still image rather than raising |
| `bad_fdat_short` | `InvalidImageContentException` | yes | the last fdAT chunk's payload is cut short, so the frame's zlib stream ends mid-way through |

## Per-fixture notes

- `dispose_none_blend_source`: APNG_DISPOSE_OP_NONE x APNG_BLEND_OP_SOURCE: the rectangle is left as it is, so the frames accumulate. Frame 0 is a full-canvas backdrop that is opaque on the left and transparent on the right; frames 1..3 are overlapping opaque 6x5 rectangles at differing offsets, and only frames 1 and 2 carry the disposal so the restore is observable against a populated canvas.
- `dispose_none_blend_over`: APNG_DISPOSE_OP_NONE x APNG_BLEND_OP_OVER: the rectangle is left as it is, so the frames accumulate. Frame 0 is a full-canvas backdrop that is opaque on the left and transparent on the right; frames 1..3 are overlapping opaque 6x5 rectangles at differing offsets, and only frames 1 and 2 carry the disposal so the restore is observable against a populated canvas.
- `dispose_background_blend_source`: APNG_DISPOSE_OP_BACKGROUND x APNG_BLEND_OP_SOURCE: the rectangle is cleared to transparent black before the next frame. Frame 0 is a full-canvas backdrop that is opaque on the left and transparent on the right; frames 1..3 are overlapping opaque 6x5 rectangles at differing offsets, and only frames 1 and 2 carry the disposal so the restore is observable against a populated canvas.
- `dispose_background_blend_over`: APNG_DISPOSE_OP_BACKGROUND x APNG_BLEND_OP_OVER: the rectangle is cleared to transparent black before the next frame. Frame 0 is a full-canvas backdrop that is opaque on the left and transparent on the right; frames 1..3 are overlapping opaque 6x5 rectangles at differing offsets, and only frames 1 and 2 carry the disposal so the restore is observable against a populated canvas.
- `dispose_previous_blend_source`: APNG_DISPOSE_OP_PREVIOUS x APNG_BLEND_OP_SOURCE: the canvas is restored to what it held before the frame was drawn. Frame 0 is a full-canvas backdrop that is opaque on the left and transparent on the right; frames 1..3 are overlapping opaque 6x5 rectangles at differing offsets, and only frames 1 and 2 carry the disposal so the restore is observable against a populated canvas.
- `dispose_previous_blend_over`: APNG_DISPOSE_OP_PREVIOUS x APNG_BLEND_OP_OVER: the canvas is restored to what it held before the frame was drawn. Frame 0 is a full-canvas backdrop that is opaque on the left and transparent on the right; frames 1..3 are overlapping opaque 6x5 rectangles at differing offsets, and only frames 1 and 2 carry the disposal so the restore is observable against a populated canvas.
- `over_alpha_exact`: APNG_BLEND_OP_OVER restricted to the degenerate cases, which are exact under any rounding: half-transparent green over the empty canvas must come back verbatim (source-over onto a transparent destination is the identity), a 0/255 alpha checkerboard must punch holes rather than blend, and an opaque rectangle over the half-transparent one must overwrite it; Pillow composites APNG_BLEND_OP_OVER as a straight lerp that also lerps alpha, so it disagrees with the specification wherever a source pixel is partly transparent.
- `over_alpha_general`: real source-over arithmetic: an alpha ramp over an opaque backdrop, then 254 at alpha 128 over an opaque black patch, then a full-canvas 25% white wash. That middle blend is (128*254 + 127*0)/255 = 127.498, only 0.002 from a rounding boundary, so this is the one fixture the exactness gate refuses and the one that carries a tolerance; Pillow composites APNG_BLEND_OP_OVER as a straight lerp that also lerps alpha, so it disagrees with the specification wherever a source pixel is partly transparent.
- `over_noop_alpha_zero`: a fully transparent full-canvas frame blended with APNG_BLEND_OP_OVER must leave the canvas exactly as it was. An implementation that treats OVER as SOURCE wipes the picture here.
- `offsets_edges`: frame rectangles on all four corners, all four edges and one exactly equal to the canvas: a mis-signed or transposed offset moves a rectangle off the edge it belongs on.
- `frame_1x1`: single-pixel frames in the corners, the middle and off-centre: the smallest legal rectangle.
- `single_frame`: acTL num_frames 1, one fcTL before IDAT and no fdAT chunk at all: a legal animation whose only frame is the still image.
- `hidden_first_frame`: the IDAT image is a still fallback that is NOT part of the animation - it is solid magenta (255,0,255,255), a colour no animation frame uses, so a decoder that emits it is caught. The first fcTL follows IDAT, the animation is the three fdAT frames only, and the canvas those three composite onto starts fully transparent; Pillow starts a hidden-default-image animation from the still image instead of the fully transparent black output buffer the specification mandates, and the first animation frame does not cover it opaquely.
- `hidden_first_frame_single`: Pillow/libpng writing a hidden default image with exactly one animation frame after it: acTL num_frames 1 with no fcTL before IDAT.
- `multi_fdat`: frame 2's compressed data is split across three consecutive fdAT chunks, so the decoder must concatenate the payloads after stripping each 4-byte sequence number.
- `multi_idat_frame0`: frame 0 (the IDAT image, which is part of the animation) is split across three IDAT chunks.
- `loop_forever`: acTL num_plays 0, which means loop forever. Written by Pillow/libpng, which cropped frames 1 and 2 to the rectangle that actually changed.
- `loop_three`: acTL num_plays 3: the animation runs three times and stops. Written by Pillow/libpng.
- `delay_den_zero`: delay_den 0 means 1/100 s by specification, so these frames must report 5/100 and 7/100 - a Rational with a zero denominator would make ToDouble() return NaN.
- `delay_exotic`: film (1/24), NTSC (1001/30000) and an explicit zero delay: the numerator and denominator must be kept verbatim rather than collapsed into milliseconds.
- `ancillary_between_frames`: tEXt and pHYs chunks sit between each fcTL and its fdAT. They must be skipped without disturbing the frame sequence numbering.
- `interlaced_adam7`: every frame is Adam7 interlaced over its own rectangle, so the seven-pass loop has to run per frame and on sub-canvas dimensions where several passes are empty; Pillow 11.3 raises TypeError from its zip decoder when it seeks to an interlaced fdAT frame, so it cannot read this file at all.
- `palette_animated`: colour type 3 at 8 bits with a shared PLTE and a tRNS that makes entry 0 transparent: the frames share one palette, use offsets and disposal, and frame 2 paints the transparent entry.
- `gray_alpha`: colour type 4 (grey + alpha) at 8 bits, including a fully transparent frame that must overwrite - not blend into - the canvas because its blend op is APNG_BLEND_OP_SOURCE.
- `gray16`: colour type 0 at 16 bits. An animated PNG composites in an Rgba32 canvas, so unlike a still 16-bit PNG loaded into Rgba64 the samples are narrowed to their high byte - the .rgba holds that narrowed value, which is the documented fidelity asymmetry of the animated path; Pillow scales 16-bit samples to 8 bits where the library narrows them to the high byte, so its decode is not the expected image.
